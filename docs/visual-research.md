# 靈體圖鑑 · 本體光譜:視覺化研究與改版說明

這份研究回答三個問題:原作好在哪、缺在哪;一個「極具視覺畫面」的 app 從何而來;以及這次改版具體做了甚麼、下一步做甚麼。

---

## 1. 原作剖析

### 1.1 資訊架構

原檔 `original/spectrum.html` 是一個單檔網頁:約 164 KB,其中 131 KB 是資料。

| 項目 | 內容 |
|---|---|
| 靈體 | 237 位,其中 79 位「已立傳」(有詳寫傳記) |
| 七環 | 法 10 · 權 40 · 力 88 · 信 27 · 念 7 · 懼 63 · 物 2 |
| 六軸 | 本體權能、影響半徑、向人性、可協商度、信仰熱度、臨界性(0–100) |
| 系統 | 希臘 140 · 香港 44 · 其他 53 |
| 語域 | 八種:冷峻文言、莊嚴史詩、英雄敘事、溫暖港式口語、家祠口吻、都市怪談、乾燥科普、終章低語 |
| 互動 | 搜尋、系統篩選、七種「光照」、側欄詳情、AI「深掘立傳」 |

### 1.2 已經做對的地方

1. **「形狀即身份」**。每位靈體的印記就是牠的六軸雷達輪廓,大小代表本體權能。這是一個真正的資料視覺化,不是裝飾。
2. **「光照」是整部作品最強的概念**。切換一條軸,整片圖鑑按那條軸重新點亮:亮的是高分,暗的是低分。它把資料篩選變成「打燈」,和「光譜」這個主題完全一致。
3. **每一環有自己的顏色與語域**。法是冷銀藍、信是琥珀、念是陶橙;文字語氣由文言到粵語口語到科普。視覺和文字同步變化,這在資料型網頁很少見。
4. **暖帶**。信與念兩環底下有一片暖色光暈,呼應「意義住在中間被相信、被記得的那段暖帶」。
5. **印章字作導航脊**:法 → 權 → 力 → 信 → 念 → 懼 → 物,一行字就是整個結構。

### 1.3 需要處理的問題

**(一)「形狀即身份」在三分之一的靈體上失效。**
237 位靈體只有 181 種不同的六軸組合;有 83 位與別的靈體共用完全相同的數值。最常見的 `[54, 54, 48, 30, 48, 36]` 由 10 位共用。牠們的印記一模一樣,讀者分不出來。這些大多是 158 位「待立傳」靈體,數值像是由模板填入。

**(二)部分數值與形象矛盾。**
例如刻耳柏洛斯(冥府三頭犬)向人性 83,落在「庇佑型,待人以暖」;塔洛斯、拉冬、阿耳戈斯都是 82。這些值得逐一核對。

**(三)核心論點沒有落在任何一條軸上。**
作品的論點是「權力與親密成反比」。但全體資料的相關係數:

| 本體權能 對 | 相關係數 r |
|---|---|
| 向人性 | +0.09 |
| 可協商度 | +0.05 |
| 信仰熱度 | −0.13 |
| 臨界性 | −0.22 |

沒有一條軸與權能明顯反向。反比關係靠的是「環的排列」和文字,而不是數據本身。建議加入第七軸「親密度」(被誰記得、記得多深),或把親密度定義為向人性、臨界性等的組合。新版 3D「軸空間」可以直接驗證這一點(見 4.1)。

**(四)沒有圖像,也沒有深度。**
全部內容都是印記加文字,視覺上限很快就到。畫面是平的,沒有前景、中景、背景之分,抽屜又以文字為主。

**(五)技術問題。**
- 「深掘立傳」直接呼叫 `api.anthropic.com` 而沒有金鑰,只在舊版 claude.ai 環境可用,其他地方一律失敗。
- 抽屜雷達的軸名超出 SVG 範圍,「影響半徑」「信仰熱度」會被切掉。
- 全部程式、樣式、資料塞在一個檔,難以維護。

## 2. 「極具視覺畫面」從何而來:十條原則

以下每一條都附上在本作的具體做法。

1. **只用一個主隱喻,並貫徹到底。** 本作的隱喻是「光」:光譜、光照、暖帶、退潮光熄。所以新版的 3D 用發光晶體、泛光(bloom)、香火餘燼;被篩走的靈體不是消失,是熄燈。
2. **分出景深層次。** 背景(星塵、霧)、中景(七環的光圈)、前景(晶體、介面)。層次一分開,游標或鏡頭一動就有視差,畫面立刻有空間感。
3. **讓資料本身長出形體。** 雷達輪廓擠出成晶體;光譜塔每一環的半徑等於該環平均「影響半徑」,所以塔身在「念」收到最窄。這個形狀是算出來的,不是畫出來的。
4. **動態要有意思,不要隨機。** 進入星宇時鏡頭由「法」降到整座塔(由法則到物質);暖帶的餘燼向上飄(香火),塔底的微粒向下沉(退潮)。每個動態都在講同一個故事。
5. **克制的色彩系統。** 七個環色加一條冷到暖的「光照」色階;墨黑底。一個畫面只讓一種環色主導。
6. **質感。** 極淡的紙紋顆粒、泛光、晶體的清漆反光。純色平面看起來像後台介面,加一點顆粒就像圖版。
7. **聲音也是視覺的一部分。** 每一環一個和弦:法是低沉的五度,力是不協和的鋸齒波,信是溫暖的五聲音階,物是濾過的白噪音。打開靈體時響一下鐘聲,權能越低,音越高、越近。
8. **圖像要有一本「風格聖經」。** AI 生成圖最大的問題是風格漂移。解決方法是一段固定的前置指令,加上把六軸數值翻譯成視覺語彙(權能高 = 巨大而遙遠;可協商度低 = 四周沒有供品;臨界性高 = 身體一部分化成霧)。這樣圖像本身也在表達資料。
9. **設計「揭曉」的一刻。** 抽籤的翻牌、測驗結果、飛到某一環。一個畫面只有一個高潮,其他地方保持安靜。
10. **可及性與退路。** 所有動態都尊重「減少動態」設定;3D 載入失敗時自動退回 2D,所有功能照用;手機上 3D 自動降低解析度。

## 3. 技術選型地圖

| 技術 | 用途 | 成本 | 本作 |
|---|---|---|---|
| CSS 3D 變換 | 卡片傾斜、翻牌、景深 | 極低 | 印記傾斜與光澤、今日靈籤翻牌 |
| SVG | 印記、雷達、圖表 | 低 | 印記、法陣、比較疊圖 |
| Canvas 2D | 點陣輸出、材質生成 | 低 | 1080×1350 分享卡 |
| WebGL / three.js | 3D 場景、粒子、著色器 | 中 | 星宇、立體台 |
| 後期處理 | 泛光、色調映射 | 中 | UnrealBloom ＋ ACES |
| 自訂著色器 | 深度位移、特效 | 中 | 肖像深度浮雕 |
| React Three Fiber | 以 React 組件寫 3D | 中 | 若日後轉 React,可平移 |
| WebGPU(three.js WebGPURenderer) | 更大量粒子、運算著色器 | 中高 | 路線圖:上千靈體時用 |
| Gaussian Splatting | 真實場景 3D 化 | 高 | 路線圖:天后廟、神台 |
| Spline / Rive / Lottie | 設計師主導的動態 | 中 | 可用於開場動畫 |
| GSAP | 複雜時間線動畫 | 低 | 目前以原生 CSS/rAF 足夠 |

選 three.js 的原因:不需要建置工具,經 import map 從 CDN 直接載入;在 claude.ai Artifact 的白名單內;生態成熟(OrbitControls、泛光、GLTF 載入器都是現成的)。

## 4. 這次改版做了甚麼

### 4.1 視覺

**星宇 3D(光譜塔)**
237 粒晶體排成七環,由上而下疊成一座塔。晶體的形狀是該靈體的六軸輪廓,大小是本體權能。每環半徑由資料計出,所以塔身在「念」最窄:離中軸最近的,是被記得的人。暖帶底下有暖光與上升的香火餘燼,塔底有下沉的「退潮」微粒。左側七枚印章可以一按飛到該環。上方的「光照」和搜尋會同步點亮或熄滅 3D 晶體。

**星宇 3D(軸空間)**
任選三條軸作 X、Y、Z,每位靈體落在對應座標,右上即時顯示 X 與 Y 的相關係數。這讓「權能與親密成反比」變成可以親眼驗證的事。

**立體台(抽屜頂部)**
- 沒有素材:顯示六軸晶體,隨游標傾斜、可拖曳旋轉。
- 放入肖像:用深度圖把平面推成浮雕,有真實視差;沒有深度圖就自動估算。
- 放入 GLB:顯示真 3D 模型,自動置中、打光、旋轉。

**其他**
印記隨游標傾斜並帶光澤;全頁極淡紙紋;今日靈籤翻牌;修正雷達軸名被切掉的問題;中文襯線字加入 Noto Serif TC,在沒有宋體的 Windows 與 Android 上也保持同一種氣質。

### 4.2 實用

| 功能 | 說明 |
|---|---|
| 相似靈體 | 抽屜內列出六軸距離最近的六位,附相近度 |
| 同環導航 | 抽屜底部前後一位;鍵盤 ← → |
| 比較 | 最多三位,疊加雷達、數值表,並自動寫出差距最大的軸與反比是否成立 |
| 收藏與遇見 | ★ 收藏、打開過即「已遇見」;頁尾按環顯示收集進度;可只看收藏 |
| 分享卡 | 一鍵生成 1080×1350 PNG;有肖像時用上肖像 |
| ChatGPT 圖像指令 | 每位靈體四種指令:圖鑑肖像、3D 建模用、四視圖、深度圖 |
| 網址錨點 | `#e121` 直接打開天后;`#cosmos`、`#omen`、`#quiz` |
| 鍵盤 | `/` 搜尋、`Esc` 關閉、`← →` 換靈 |

### 4.3 有趣

| 功能 | 說明 |
|---|---|
| 今日靈籤 | 按日期固定抽一位已立傳靈體;最高分的軸決定「宜」,最低分的軸決定「忌」 |
| 本命靈測驗 | 六條題目各對應一條軸,用六軸距離找出最接近的已立傳靈體,疊圖比較「你」與「祂」 |
| 聲景 | 每環一個和弦,捲動或打開靈體時切換 |
| 深掘立傳 | 在 Claude 內開啟時,以該環語域即場續寫詳盡傳記 |
| 向祂問一句 | 在 Claude 內開啟時,以該靈體第一身回答;權能越高越冷漠,向人性越高越溫柔 |

AI 功能改用 Claude Artifact 的 `sample` 能力,用觀看者自己的 Claude 額度,毋須金鑰;在 Claude 以外開啟時會說明要在哪裏才能用,而不是報錯。

### 4.4 程式結構

```
index.html              頁面骨架、import map
src/styles.css          原檔樣式 ＋ 新元件
src/data/entities.js    237 位靈體(原資料,未改動)
src/data/lore.js        六軸、七環、語域(原常數)＋ 美術方向、測驗、靈籤、聲景
src/prompts.js          ChatGPT 圖像指令產生器
src/core.js             圖鑑、印記、法陣、抽屜、AI
src/features.js         收藏、立像、比較、分享卡、測驗、靈籤、聲景
src/stage3d.js          立體台(晶體／深度浮雕／GLB)
src/cosmos3d.js         星宇 3D
src/main.js             啟動與事件
assets/manifest.js      立像登記冊
tools/gen-prompts.js    產生 79 位靈體的指令集
```

全部是不需建置的原生 JavaScript,直接開 `index.html` 就能用;要載入 `assets/` 內的肖像與模型時,請用本機伺服器開啟(見 README)。

## 5. 路線圖

**資料(影響最大)**
1. 為 158 位待立傳靈體補回真實數值,消除 83 位的重複雷達。
2. 核對異常值(刻耳柏洛斯、塔洛斯、拉冬等的向人性)。
3. 加入第七軸「親密度」,讓核心論點落在數據上。

**圖像**
4. 用 [`chatgpt-image-prompts.md`](chatgpt-image-prompts.md) 先做七環主視覺,放進每一環的頁首。
5. 按 [`prompts/flagship-prompts.md`](prompts/flagship-prompts.md) 為 79 位已立傳靈體生成肖像與深度圖。
6. 每環挑一至兩位做 GLB 模型(建議:安那刻、哈得斯、美杜莎、天后、夢訪靈、白衣女鬼、鬼火)。

**3D**
7. 星宇按距離切換:遠看晶體,拉近換成模型。
8. 以 Gaussian Splatting 把真實的天后廟、祖先神台放進「信」「念」兩環。

**社群(Artifact 的共享能力)**
9. 「你遇過邊位?」:用共享資料庫讓讀者為靈體投票、留下自己的遭遇,在 3D 裏以光點顯示熱度。
