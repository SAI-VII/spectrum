# 視覺層面的最佳級別:研究與執行方案

上一份研究([`visual-research.md`](visual-research.md))回答了「這個 app 怎樣變得好看」。這一份回答下一個問題:**怎樣做到最好**。結論先放在前面,之後逐項展開,每一項都寫明本專案已做了甚麼、還要做甚麼。

---

## 0. 結論:五件影響最大的事

按「效果 ÷ 成本」排序:

1. **一致性比精細度重要。** 237 座雕像只要有 20 座風格不同,整部圖鑑就會像素材庫。所以先定下每位靈體的「視覺正典」(外形、法器、姿態、材質),再由同一套規則生成所有指令。**已完成**:`src/data/canon.js` 237 條,`src/prompts.js` 統一組裝。
2. **用參考圖做 3D,不要只靠文字。** Meshy 7 系列的賣點是「圖像與 3D 對齊」:形體跟參考圖走。先用 ChatGPT Images 2.5 生成灰底雕像參考圖,再做 Image to 3D,形體和配色都可控。**已完成**:參考圖指令(按環每 4 位一批)、批量生成程式。
3. **燈光決定質感。** 同一個模型,平光下像塑膠,三點布光加環境反射就像博物館藏品。每一環有自己的攝影棚:暖白主光、環色輪廓光、環色環境反射、接觸陰影。**已完成**:立體台與縮圖渲染共用同一套配方。
4. **縮圖要統一渲染。** Meshy 回傳的預覽圖各有角度和背景,拼在一起很亂。自己用同一鏡頭、同一燈光重新渲染 237 張透明背景縮圖,圖鑑一打開就像一套收藏卡。**已完成**:`tools/meshy/thumbs.mjs`。
5. **後期要克制。** 泛光只給發光體,暗角、色散、菲林顆粒都壓到幾乎看不見。觀眾不應察覺「用了特效」,只覺得畫面「像電影」。**已完成**:星宇 3D 的泛光門檻調高,另加一道調色。

## 1. 「最佳級別」長甚麼樣

參考對象不是其他資料網頁,而是這幾類作品:

| 參考類型 | 例子 | 值得學的地方 |
|---|---|---|
| 遊戲內圖鑑 | Supergiant《Hades》的圖鑑、Pokémon 圖鑑的 3D 展示 | 每個角色同一套畫風、同一種卡框、同一個鏡頭;文字有語氣 |
| 博物館線上藏品 | 大英博物館、故宮的 3D 文物 | 燈光與材質真實,可以轉、可以放大,資料與實物並排 |
| 產品展示頁 | 高端電子產品發佈頁 | 鏡頭運動有編排,每一幕只講一件事 |
| three.js 作品集網站 | Bruno Simon 等創作者的互動網站 | 3D 與介面融為一體,載入有儀式感 |

共通點只有三個:**同一套美術規則貫徹到底;燈光和材質可信;動態有編排、有節制。** 解析度、面數、特效數量都排在後面。

## 2. 七個支柱

### 2.1 美術一致性

| 規則 | 本專案做法 |
|---|---|
| 一本風格聖經 | [`chatgpt-image-prompts.md`](chatgpt-image-prompts.md) 第 2 節,每個 ChatGPT 對話先貼 |
| 每位靈體一條正典 | `canon.js`:kind、外形、法器、姿態、材質 |
| 每環一套材質語言 | 法:銀藍石與銀線;權:大理石與金箔;力:暗青銅與朱漆;信:樟木紅漆金箔(港式廟宇神像);念:手撫檀香木;懼:霧化半透明樹脂;物:博物館石膏與玻璃 |
| 每環一個底座 | 七款六角底座,材質對應各環,令雕像並排時一眼分得出屬哪一環 |
| 數據決定畫面 | 本體權能 → 鏡頭角度與焦距;向人性 → 光的冷暖軟硬;可協商度 → 供品;信仰熱度 → 燈火數量;臨界性 → 霧 |

**港式神像要準。** 關帝紅面長鬚綠袍、天后冕旒紅袍、北帝踏龜蛇、車公風車、福祿壽三星的法器,這些已寫進正典。生成後逐位對照(見第 5 節)。

### 2.2 資產質素(Meshy)

| 設定 | 建議 | 原因 |
|---|---|---|
| 模型 | `latest`(目前 meshy-7.1) | 7.1 的幾何細節比 7 更豐富,點數相同 |
| 來源 | 已立傳 79 位用參考圖;其餘用文字 | 參考圖可控,文字省人手 |
| 參考圖 | 1:1、3/4 前側、85mm、灰底、平光、無陰影 | image-to-3D 最怕透視變形、投影、雜物 |
| 雕塑規則 | 一件連體實心;細線加粗;煙火水霧雕成實體 | 避免浮空碎片和穿孔 |
| 面數 | Meshy 產 100,000 面,網頁版再減到 60,000 / 4,000 | 保留高模做母版,網頁版按用途減 |
| 貼圖 | PBR 開;已立傳可用 4K | 金箔、漆面、大理石要靠粗糙度與金屬度 |
| 去光照 | 保持 Meshy 預設(開) | 貼圖不帶烘焙陰影,app 的燈光才能發揮 |
| 幾何解析度 | 已立傳可用 `--geometry 2k` | 臉和手的細節明顯改善,每位多 5 點 |

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 背面亂長 | 改用四視圖(Multi-Image to 3D) |
| 浮空碎片、細線斷開 | 參考圖指令已要求加粗與連體;仍出現就在正典裏刪掉那件細物 |
| 群像黏成一團 | 群像(命運三女神、九繆斯等)改為「三人背靠背」「半圓排列」這類緊湊構圖,已寫進正典 |
| 臉部崩壞 | 參考圖改近一點的鏡頭;或把姿態改得更正面、更簡單 |
| 顏色偏離本環 | 在 Meshy 的 texture prompt 用 app 內「Meshy 貼圖」指令;或把 `--texture-prompt` 加入 Image to 3D |

### 2.3 燈光

立體台與縮圖渲染用同一套配方(`src/stage3d.js`、`tools/meshy/thumb.html`):

| 燈 | 設定 | 作用 |
|---|---|---|
| 環境反射 | 以 PMREM 把一個小攝影棚轉成環境光:左上前方暖白柔光箱、後方兩條本環色燈條、地面微弱反光 | 金屬與漆面反射出本環顏色,七環的雕像各有氣質 |
| 主光 | 暖白(#FFF4E6)方向光,左上前方 | 形體與臉部 |
| 輪廓光 | 本環色方向光兩盞,右後與左後 | 把剪影從黑底切出來,也是顏色識別 |
| 接觸陰影 | 腳底放射漸層 | 令雕像「站在」台上,不是浮着 |
| 色調映射 | ACES Filmic,曝光 1.0 | 高光柔和滾降,不會死白 |

### 2.4 後期

| 效果 | 設定 | 原則 |
|---|---|---|
| 泛光 | 強度 0.6、半徑 0.42、門檻 0.42 | 只讓發光體發光;門檻太低整個畫面會灰 |
| 背景 | 經 ACES 後等於頁面墨色 #0E1015 | 3D 與網頁無縫 |
| 暗角 | 角落暗約 45% | 視線集中在中軸 |
| 色散 | 只在畫面邊緣,極輕 | 鏡頭質感,不能令文字起彩邊 |
| 菲林顆粒 | 3% | 去除數碼平滑感;減少動態模式下不跳動 |
| 抗鋸齒 | 4× MSAA 渲染目標 | 後期處理下保持邊緣乾淨 |

### 2.5 動態

- **開場有故事**:進入星宇時鏡頭由「法」降到整座塔,就是「由法則到物質」。
- **一幕一重點**:飛到某一環、打開某一位、翻開靈籤,每次只做一件事。
- **速度要有重量**:權能高的晃動慢而小,暖帶的餘燼向上,退潮的微粒向下。
- **尊重減少動態設定**:自動旋轉、晃動、顆粒閃動全部停止,功能照用。
- **可選:骨架動畫**。Meshy 的 Auto-Rigging(5 點)與動畫(每段 3 點)只適合人形。可為 20 位人形主神加一段待機呼吸動畫,app 的立體台已會自動播放 GLB 內的第一段動畫。

### 2.6 互動

- 雕像可拖曳、滾輪縮放、全螢幕;停手幾秒自動慢轉。
- 星宇內懸停出名牌,點選飛近並打開抽屜。
- 「光照」同時改變雕像:圖鑑縮圖以亮度與飽和度重新點亮,星宇內的雕像按數值發光。
- 聲景:每環一個和弦,打開靈體時響一下鐘聲。

### 2.7 效能預算

| 項目 | 預算 |
|---|---|
| 展示版模型 | ≤ 60,000 面、貼圖 ≤ 2048、單檔約 1–3 MB,只在打開抽屜時載入 |
| 輕量版模型 | ≤ 4,000 面、貼圖 256、單檔約 50–150 KB |
| 星宇同時載入 | 3 個並行,按離鏡頭遠近;桌面最多 260 座,手機 80 座 |
| 星宇總三角面 | 約 237 × 4,000 ≈ 95 萬,桌面顯示卡輕鬆 |
| 顯示記憶體 | 輕量版 256² 貼圖 × 3 張 × 237 ≈ 60 MB |
| 縮圖 | 384² WebP,每張約 15–25 KB,延遲載入 |
| 壓縮格式 | WebP ＋ Meshopt(Artifact 可用);自架網站可再換 KTX2 省顯示記憶體 |

## 3. 由「好」到「最好」的四級路線

| 級別 | 內容 | 狀態 |
|---|---|---|
| **一 · 已完成** | 視覺正典、指令產生器、Meshy 批量程式、兩級網頁模型、統一縮圖、展示櫃立體台、星宇雕像串流、調色後期 | 本次提交 |
| **二 · 批量生成** | 跑完 237 位;按第 5 節逐位檢查;重做不合格的 | 需要你的 Meshy 點數 |
| **三 · 精修 20 位** | 每環挑 2–3 位主角(安那刻、哈得斯、宙斯、美杜莎、提豐、天后、關帝、黃大仙、祖先靈、夢訪靈、白衣女鬼、鬼火⋯)在 Blender 補細節:金箔用清漆層、大理石加次表面散射、港式神像補面部彩繪;加待機動畫 | 建議 |
| **四 · 空間化** | 用七環主視覺經「圖生 3D 世界」工具(如 World Labs Marble)做成 Gaussian Splat 場景,以 Spark 或 three.js r186 起內建的 splat 渲染器放進星宇,每一環變成可走進去的空間;three.js 轉 WebGPU 渲染器以承托更多粒子 | 路線圖 |

第四級值得說明:three.js 在 r186 起內建 Gaussian Splat 渲染與點選;World Labs 的 Spark 2.0 可串流上億個 splat 並與一般網格同場渲染。「信」環的天后廟、「念」環的家中神台,都可以由一張 ChatGPT 主視覺生成可環視的場景,雕像放在場景裏。WebGPU 自 Safari 26(2025 年 9 月)起已獲所有主流瀏覽器支援,three.js 的 WebGPURenderer 在不支援時自動退回 WebGL 2。

## 4. 指令寫法的改進(第二版)

第一版指令只用資料欄位(職權、手段)拼湊,結果是抽象形容詞多、具體名詞少。第二版的改變:

| 第一版 | 第二版 |
|---|---|
| 由「職權、手段」推想外形 | 每位有人手寫的外形、法器、姿態、材質 |
| 一段長文 | 按 OpenAI 建議的次序分段:場景 → 主體 → 細節 → 鏡頭與光 → 風格 → 限制 |
| 六軸只變成形容詞 | 權能決定鏡頭焦距與角度、向人性決定光的冷暖軟硬 |
| 3D 用指令只要求灰底 | 加入雕塑規則:連體、加粗細線、煙火水霧雕成實體、避免透明與鏡面 |
| 沒有 Meshy 專用指令 | Meshy 文字指令:最重要的詞放最前,按優先次序刪減到 600 字元內 |
| 一次一張 | 3D 參考圖按環每 4 位一批,Images 2.5 一次生成多張並保持一致 |

## 5. 每一座雕像的品質檢查表

生成後逐位在 app 內打開立體台檢查。任何一項不合格就重做(`--only 編號 --redo`)。

| # | 檢查 | 合格標準 |
|---|---|---|
| 1 | 剪影 | 縮到 64 px 仍認得出是誰(法器、頭飾、翅膀、尾巴) |
| 2 | 身份 | 正典裏的法器都在,數目正確(九頭蛇九個頭、三女神三個人) |
| 3 | 文化準確 | 港式神像的面色、冠飾、袍色、法器與廟宇造像一致 |
| 4 | 本環材質 | 一眼看得出屬哪一環(底座與材質) |
| 5 | 結構 | 沒有浮空碎片、穿孔、破面;底座平而完整 |
| 6 | 方向 | 正面朝前(+Z),站直 |
| 7 | 臉與手 | 沒有扭曲、多指、融合 |
| 8 | 背面 | 合理,沒有奇怪的延伸 |
| 9 | 貼圖 | 沒有明顯接縫、模糊、烘焙陰影 |
| 10 | 規格 | 展示版 ≤ 60,000 面、≤ 3 MB;輕量版 ≤ 4,000 面、≤ 150 KB |

## 6. 執行次序

1. 按 [`meshy-pipeline.md`](meshy-pipeline.md) 第 1–2 步試跑與乾跑。
2. 先做一環試水(建議「信」,27 位,約 810 點),檢查一致性與文化準確度,必要時修改 `canon.js` 或 `lore.js` 的 `BAND_ART`。
3. 做已立傳 79 位(參考圖路線)。
4. 做其餘 158 位(文字路線)。
5. 優化、渲染縮圖、逐位檢查、重做。
6. 精修 20 位主角(第三級)。
